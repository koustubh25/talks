Agent value-add: workflow automation

So the agent is a black box.

You handed the decisions to an agent, but your CI only knows lint, types and tests. They check the code around the box, never inside it.

each of those checkpoints is an eval that scores one step inside the box.

It's a pop quiz for your agent.

eval =
datareal questions from real users, not ones you wrote to pass
+
taskyour agent, doing its actual job
+
scoreone verdict per answer: pass or fail

That's it. Just data analysis, no new math.

You can't hand-grade 10,000 chats, so grade a model with a model.

binarypass / fail. a "3.2 vs 3.7" never blocked a merge in its life.
narrowone judge, one failure mode. an "overall quality" judge judges nothing.
judge the judgecheck it against human labels first. yes, test your test.
Azure: Microsoft Foundry ships these as built-in evaluators, and its own docs call them binary Pass/Fail, just like unit tests. Add your own as code, prompt, or endpoint checks.

Now wire that judge into CI.

The gate never asks "is the candidate good?" It asks "is it worse than production today?"

Azure: microsoft/ai-agent-evals does exactly this in a GitHub Action, promoting versions Dev → Test → Prod.

What the gate actually measures.

Of those checkpoints from earlier, two carry our whole story:

task adherencedid it follow its own rules? search first, don't invent, book correctly.
tool groundingis the answer backed by what the tools returned, or made up?

Agents are flaky, so one run isn't enough. The gate reports a p-value: is this regression real, or just luck?

8/30 candidate vs 23/30 baseline and we'll watch it decide a merge, live.

A green gate is not safety.

Your suite only knows the failures you've already seen. The rest is on you. Sample real traffic, read the traces, label what's wrong, feed it back.

Put on the PM hat. This judgment is the part no platform does for you.
evals are the PRD that actually runs, and it's never finished. error analysis is the moat.
