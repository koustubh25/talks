Your agent doesn't need to fail once. It needs to succeed every single step — and every extra tool call is another coin flip.

Why the old tools stop working

Unit tests check answers.
Agents make judgment calls.

assert booking.confirmed == true

Known input. Known output. One correct answer, checkable in milliseconds.

assert conversation.wasGood == ???

Unbounded input. No single right answer — a domain expert would still argue about it.

Try to assert() your way through that and you get: ¯\_(ツ)_/¯

The fix

Same job as a failing test.
A smarter judge.

An eval gate is a check — code-based, or an LLM-as-judge — wired into your pipeline. It fails, the merge blocks. That's it. That's the whole idea.

✓ Task Adherence ✓ Tool Call Accuracy ✓ Intent Resolution ✓ Tool Output Utilization

Most teams land on ~4–7 of these total. Not hundreds.

The honest part

Bugs will still happen.
Let's not pretend otherwise.

Nothing fully prevents an AI bug in production — same as nothing prevents one in any complex system. What a gate buys you: it catches what you already know to test for, and shrinks the blast radius on what you don't.

An eval suite that never fails isn't safe — it just isn't looking hard enough.

So what happens when something slips through anyway? Let's watch it happen.
